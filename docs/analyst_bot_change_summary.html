문서 안 용어

분석 세션은 Slack 스레드 하나에 붙는 이어지는 분석 대화다. dbt는 SQL을 정리하고 컴파일하는 도구, BigQuery는 실제 데이터를 조회하는 저장소, Metabase는 결과를 카드나 대시보드로 보는 화면이다. Docker 마운트는 호스트 파일 일부를 컨테이너 안에 보여주는 설정이고, 도구 허용 목록(permission list)은 Claude가 쓸 수 있는 도구 목록이다. macOS 로그인 보관소(Keychain)는 macOS가 로그인 정보를 보관하는 곳이다.

실행 기록은 봇이 남기는 자세한 근거 파일이다. Slack에는 숨긴 검증, 재현 SQL, 실행 전 점검값, 도구 실행 원문이 여기에 들어간다. 실행 전 점검은 실제 쿼리를 돌리기 전에 비용과 범위를 확인하는 단계다. 명령 이름에는 --dry-run이라는 표현이 남아 있지만, 이 문서에서는 “설정 점검” 또는 “실행 전 점검”으로 풀어 쓴다.

협업 메모

작업 중 계속 잡았던 기준은 “분석자용 근거는 로그, Slack은 의사결정 화면”이었다. 햄찌를 너무 딱딱한 감사자가 아니라, Slack에서 옆자리 동료처럼 말하는 분석 파트너로 두자는 쪽으로 톤을 맞췄다.

오늘 작업은 결과를 보면서 계속 고친 루프였다

1

검증/재현 라인이 Slack에 남았다

본 답변검증:, 재현:, SQL 경로가 최종 답변에 보였다.
판단질문자는 결론을 보려는 것이지, 분석자가 재현할 로그를 읽으려는 것이 아니다.
수정검증/재현/운영 상세 라인을 제거하고 실행 기록으로 보냈다.
2

Docker 안에서는 호스트 Claude 로그인이 넘어오지 않았다

본 결과컨테이너에서 Claude 인증이 없어 실행이 막혔다.
판단호스트 ~/.claude를 마운트하면 격리 목적이 깨진다.
수정컨테이너 안에서 Claude 로그인을 한 번 수행하고 Docker 저장 공간에 보관했다.
3

첫 실제 Slack 테스트 답변이 너무 기술적으로 읽혔다

본 답변active actor, actor.id, UTC가 앞에 나왔다.
판단정확한 지표명보다 먼저 사람이 이해하는 말이 나와야 한다.
수정활동 계정, 계정 ID, 데이터 기준으로 바꾸는 용어표를 넣었다.
4

“간단히”라는 요청에도 답이 길어질 수 있었다

본 답변비교표와 추가 진단이 따라붙을 수 있었다.
판단짧게 물은 질문에는 짧게 답하는 것도 기능이다.
수정간단히, 짧게, quickly, tl;dr는 2-4문장 + 한계 한 줄로 제한했다.
5

말투가 아직 감사 노트처럼 느껴졌다

본 느낌기능은 되지만 Slack 동료가 말하는 느낌은 약했다.
판단햄찌의 장점은 친근한 톤이었다. 다만 캐릭터 놀이가 아니라 일하는 동료 톤이어야 한다.
수정APPEND_SYSTEM_PROMPT에 “Slack에서 도와주는 동료처럼 답하기” 기준을 넣었다.

실제 테스트 질문

Docker로 띄운 뒤 Slack에서 “최근 완료된 1일 active actor 수 간단히 봐줘”라고 물었다. 기능은 성공했다. 봇은 Slack 이벤트를 받고, BigQuery를 조회하고, 답변까지 게시했다. 하지만 답변이 active actor, actor.id, UTC, 토요일 비교표까지 포함해 “간단히”라는 요청에 비해 너무 기술적으로 읽혔다. 그래서 아래처럼 목표 답변 형태를 다시 잡았다.

Slack UX

스키마 용어를 먼저 내세우지 않고, 사람이 읽는 말로 바꿨다

Slack 답변은 데이터 모델을 설명하는 문서가 아니다. 그래서 지표명은 유지하되, 첫 표현은 질문자가 바로 이해할 수 있는 말로 바꾼다. 원래 스키마 기준이 꼭 필요하면 한계 문장이나 괄호 안에서 보충한다.

기술 표현 Slack 표현 의도
active actor 활동 계정 지표는 유지하되 먼저 읽히는 말로 보여준다.
actor.id 계정 ID 필요할 때만 원래 기준을 괄호로 보충한다.
event 활동 기록 데이터 테이블 냄새를 줄인다.
UTC 데이터 기준 시간대 설명은 남기되 첫 화면을 덜 딱딱하게 만든다.
mart/raw/shard/partition/grain 필요하면 풀어서 설명 내부 구조는 답변의 주인공이 아니게 한다.

기술 변경

Docker를 빼면 변경은 다섯 가지 축으로 정리된다

2번 꼭지는 자칫 구현 목록처럼 보이기 쉬워서, “무슨 문제를 줄였는가” 기준으로 묶었다. 핵심 파일은 거의 scripts/slack_analyst_bot.py에 모여 있다.

여기서 중요한 점은 Claude의 분석 능력을 줄인 것이 아니라, 분석 과정과 사용자 답변 사이에 제품용 정리 단계가 생겼다는 것이다. 모델은 여전히 검증하고, 쿼리를 실행하기 전에 비용을 확인하고, 필요한 SQL을 저장한다. 다만 그 과정 전체를 Slack에 그대로 보여주지 않는다.

최종 답변 처리 파이프라인

1 · Claude 원문 답변
모델은 분석 절차를 모두 수행한다 검증, 실행 전 비용 점검, 재현 SQL 저장 같은 작업은 계속 한다. 바뀐 것은 그 세부를 Slack에 그대로 내보내지 않는다는 점이다.
2 · 불필요한 머리말 제거
답변 위에 붙은 자기소개와 구분선을 제거 분석 완료, 아래가 답변입니다, ---처럼 사용자가 볼 필요 없는 머리말을 걷어낸다.
3 · 내부 라벨 제거
내부 체크리스트 라벨 제거 모드, 인풋, 관측 grain, 세그먼트, 성공 지표는 분석자에게만 의미가 있다.
4 · 운영 상세 제거
운영 증거를 Slack에서 제거 dry run(실행 전 점검), bq query, dbt compile, Claude N턴, BigQuery N GiB, SQL 파일 경로는 실행 기록으로 간다.
5 · 쉬운 용어로 치환
스키마 말을 Slack 말로 바꿈 active actor는 활동 계정, actor.id는 계정 ID, event는 활동 기록처럼 바꾼다.
6 · 길이 줄이기
2,500자 안에 결론과 한계만 남김 긴 답변이 나오면 첫 결론과 핵심 문단, 한계 문단을 보존하고 나머지는 줄인다.

slack_progress_line() Claude 도구 실행 원문을 사람이 읽는 진행 상태로 바꾼다. 도구명 대신 “데이터를 조회하고 있습니다” 같은 문구 노출
build_command() / 세션 관리 객체 스레드별 Claude 분석 세션 생성·이어가기와 실행 순서를 관리한다. 같은 스레드에서 답변 순서가 꼬이지 않게 제어

Docker

Docker는 배포 편의보다 권한 경계 때문에 넣었다

로컬 세션 도구는 레포 밖 파일을 읽을 수 있었다. 이름 기반 deny만으로는 충분하지 않아서, 실제 운영 경계는 Claude 도구 허용 목록이 아니라 컨테이너에 어떤 폴더를 보여줄지 정하는 마운트 설정으로 잡았다.

여기서 Docker의 역할은 “어디서나 쉽게 실행”보다 “볼 수 있는 파일을 줄이기”에 가깝다. 컨테이너 안에는 분석에 필요한 레포 조각과 읽기 전용 BigQuery 키만 넣고, 운영자 개인 키나 호스트의 Claude 로그인 파일은 넣지 않는다. 그래서 컨테이너 안에서 파일 읽기 권한이 넓더라도 실제로 볼 수 있는 민감 파일이 없다.

  • 운영자 키와 개인 설정
  • ~/.claude, macOS 로그인 보관소(Keychain)
  • gcp-key.json, secrets/
  • 레포 전체 쓰기 권한

로그인 방식

호스트 로그인을 그대로 넘기지 않는다. 컨테이너 안에서 한 번 Claude 계정 로그인을 하고, 결과는 analyst-claude라는 Docker 저장 공간에 저장한다. 이후에는 컨테이너를 껐다 켜도 같은 로그인을 재사용한다. 

docker compose run --rm -it --entrypoint claude analyst-bot auth login

현재 상태

백그라운드 실행은 확인됐고, 다음은 실제 Slack에서 쉬운 말투를 다시 확인하는 것이다

항목 상태 메모
완료 이미지 빌드 docker compose build analyst-bot 통과 컨테이너 시작 스크립트, gcloud, dbt, BigQuery CLI 경로 확인
완료 설정 점검 docker compose run --rm analyst-bot --dry-run 통과 실제 분석은 하지 않고 레포, 실행 기록 저장 위치, gcloud 위치, 쿼리 스캔 기본 상한을 확인
완료 세션 이어가기 자체 점검 docker compose run --rm analyst-bot --self-test 통과 첫 질문 뒤 같은 Slack 스레드의 후속 질문을 이어서 처리할 수 있는지 확인
완료 백그라운드 실행 docker compose up -d analyst-bot 후 Slack 실시간 연결 로그에 Bolt app is running! 표시
남음 실제 Slack 말투 확인 첫 실제 Slack 테스트는 기능 통과, 말투가 기술적으로 읽힘 용어와 짧은 답변 규칙을 보강했으므로 같은 질문을 다시 던져 쉬운 답변으로 보이는지 확인
남음 Metabase 카드 생성 확인 METABASE_API_KEY 필요 카드 생성과 Slack 버튼 노출 확인
남음 BigQuery 강제 사용량 제한 콘솔 설정 필요 .bigqueryrc는 기본값이지 완전한 하드 상한은 아님
