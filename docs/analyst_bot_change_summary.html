Workflow

햄찌에서 가져온 건 코드보다 운영 감각이다

오래 돌던 hamji-portable-20260801을 보면서 그대로 베끼기보다, 지금 봇에 꼭 필요한 습관만 골랐다. 질문을 받으면 기다리는 사람에게 진행 상황을 보여주고, 답변은 바로 읽히게 만들고, 자세한 근거는 나중에 확인할 수 있게 따로 남기는 방식이다.

01
Slack 질문

멘션이나 DM으로 들어온 질문을 하나의 분석 턴으로 잡는다.

02
진행 메시지

복잡한 로그 대신 사람이 읽는 상태와 중단 버튼을 보여준다.

03
분석 실행

Claude, dbt, BigQuery를 쓰되 내부 경로와 비용 상세는 숨긴다.

04
답변 정리

게시 직전에 기술 메모, 재현 경로, 토큰 패턴을 걷어낸다.

05
Slack 최종 답변

결론, 핵심 숫자, 기준일/기간, 한계만 남긴다.

협업 메모

작업 중 계속 잡았던 기준은 “분석자용 근거는 로그, Slack은 의사결정 화면”이었다. 햄찌를 너무 딱딱한 감사자가 아니라, Slack에서 옆자리 동료처럼 말하는 분석 파트너로 두자는 쪽으로 톤을 맞췄다.

Slack UX

답변이 보고서가 아니라 대화처럼 읽히게 바꿨다

이전 느낌

  • 검증:, 재현: 같은 분석자용 라인이 보였다.
  • dry run, bq query, Claude N턴 같은 운영 흔적이 섞였다.
  • active actor, actor.id, UTC가 그대로 나와 답변이 기술 문서처럼 보였다.
  • 사용자가 “간단히”라고 해도 표와 추가 비교가 붙을 수 있었다.

바뀐 느낌

  • 첫 줄은 결론으로 시작한다.
  • 핵심 숫자와 기준일/기간을 바로 보이게 둔다.
  • 한계는 한 줄로 분리한다.
  • 짧게 물으면 2-4문장 안에서 끝낸다.
기술 표현 Slack 표현 의도
active actor 활동 계정 지표는 유지하되 먼저 읽히는 말로 보여준다.
actor.id 계정 ID 필요할 때만 원래 기준을 괄호로 보충한다.
event 활동 기록 데이터 테이블 냄새를 줄인다.
UTC 데이터 기준 시간대 설명은 남기되 첫 화면을 덜 딱딱하게 만든다.
mart/raw/shard/partition/grain 필요하면 풀어서 설명 내부 구조는 답변의 주인공이 아니게 한다.

Implementation

Docker를 빼면 변경은 다섯 가지 축으로 정리된다

2번 꼭지는 자칫 구현 목록처럼 보이기 쉬워서, “무슨 문제를 줄였는가” 기준으로 묶었다. 핵심 파일은 거의 scripts/slack_analyst_bot.py에 모여 있다.

Final answer
게시 직전 후처리

format_final_answer_for_slack()에서 메타 서문, 내부 라벨, 운영 상세, secret 패턴을 정리한다.

Session
스레드별 순서 보장

Slack thread 하나를 Claude session 하나로 묶고, 같은 thread는 FIFO로만 실행한다.

Control
중단과 heartbeat

긴 작업 중 멈춘 것처럼 보이지 않게 진행 메시지를 갱신하고, 사용자가 중단할 수 있게 했다.

Audit
근거는 로그로 이동

질문, 상태, Claude turn, BigQuery 사용량, raw trace, 피드백을 logs/analyst-bot/에 남긴다.

Metabase
선택 기능으로 연결

API key가 있을 때만 MCP config를 주입하고, Slack에는 카드/대시보드 링크만 노출한다.

Cost guard
비용 경계 명확화

.bigqueryrc로 기본 스캔 상한을 넣고, 하드 quota는 콘솔 설정이 필요하다고 문서화했다.

Contract

Slack에 보이면 안 되는 것들을 계약으로 박았다

Slack에 남김 로그로 보냄
결론, 핵심 숫자, 기준일/기간 검증:, 재현:, SQL 파일 경로
판단에 필요한 한계 dry run, bq query, dbt compile
Metabase 카드/대시보드 링크 MCP 이름, API key, collection id, permission 내부값
실행이 길어질 때의 진행 상태 Claude turn 수, BigQuery GiB, raw trace
검증

uv run pytest tests/test_slack_analyst_bot.py 기준 29 passed. 답변 후처리, 캐주얼 용어 치환, Metabase MCP config, 중단 버튼, 피드백 버튼, Slack raw error 은닉을 회귀에 포함했다.

Container

Docker는 배포 편의보다 권한 경계 때문에 넣었다

로컬 세션 도구는 레포 밖 파일을 읽을 수 있었다. 이름 기반 deny만으로는 충분하지 않아서, 실제 운영 경계는 Claude permission list가 아니라 컨테이너 마운트로 잡았다.

컨테이너 안에 넣는 것

  • 필요한 레포 경로를 읽기 전용으로 mount
  • read-only BigQuery 서비스 계정 키
  • ad-hoc SQL을 쓸 dbt/gharchive_metrics/analyses/
  • dbt target, Claude credential, audit state용 named volume

컨테이너 밖에 두는 것

  • 호스트 ~/.claude 전체
  • 운영자 GCP 키
  • /app/secrets, /app/gcp-key.json
  • 레포 전체 쓰기 권한
로그인 방식

호스트 로그인을 그대로 넘기지 않는다. 컨테이너 안에서 한 번 OAuth 로그인하고, 결과는 analyst-claude named volume에 저장한다. 

docker compose run --rm -it --entrypoint claude analyst-bot auth login

Runbook

headless 실행은 확인됐고, 다음은 톤 재-canary다

항목 상태 메모
완료 build docker compose build analyst-bot 통과 entrypoint, gcloud, dbt, bq 경로 확인
완료 dry-run docker compose run --rm analyst-bot --dry-run 통과 repo/state/gcloud 위치와 scan ceiling 확인
완료 self-test docker compose run --rm analyst-bot --self-test 통과 session 생성과 --resume 동작 확인
완료 headless docker compose up -d analyst-bot 후 Socket Mode 연결 로그에 Bolt app is running! 표시
남음 Slack tone canary 첫 canary는 기능 통과, 말투가 기술적으로 읽힘 용어와 짧은 답변 규칙 보강 후 재확인 필요
남음 Metabase canary METABASE_API_KEY 필요 카드 생성과 Slack 버튼 노출 확인
남음 BigQuery hard quota 콘솔 설정 필요 .bigqueryrc는 기본값이지 완전한 하드 상한은 아님

기본 운영 명령

docker compose logs -f analyst-bot
docker compose run --rm analyst-bot --dry-run
docker compose run --rm analyst-bot --self-test
docker compose up -d analyst-bot
