Slack 분석 봇 hamji 운영 패턴 적용 변경점

작성일: 2026-08-01 · 업데이트: 2026-08-02 · 대상: scripts/slack_analyst_bot.py

/Users/kakao/Downloads/hamji-portable-20260801의 오래 운영된 Slack/Bolt 기반 분석 봇 구현을 검토했고, 현재 BDA 2의 Python 단일 러너 구조에 맞는 부분만 축소 적용했다. TypeScript 구조를 그대로 이식하지 않고, 운영 마감 품질에 직접 영향을 주는 Slack 표면, 실행 제어, 감사 가능성을 우선 처리했다.

이번 변경은 BigQuery 분석 실행이 아니라 봇 러너 개선이다. 따라서 GitHub Archive raw/mart 조회는 수행하지 않았다.

hamji에서 가져온 판단

hamji 운영 패턴 BDA 적용 방식 이유
Slack 메시지를 제품 UI로 보고 pending/progress/final/error를 분리 최종 답변 sanitize/Slack mrkdwn 변환/길이 제한 레이어 추가 “분석 완료”, “아래가 답변입니다”, 모드: 활동량, 인풋, --- 같은 내부 scaffolding이 사용자에게 노출되는 문제를 차단
스레드별 keyed lock으로 같은 thread의 turn을 직렬화 기존 단순 lock을 FIFO queue로 교체하고 전역 --max-workers 상한 추가 빠른 연속 질문에서 답변 순서 역전과 Claude transcript 분기를 줄임
진행 메시지에 heartbeat와 취소 action 제공 진행 메시지에 elapsed, “중단하기” 버튼, 30초 무응답 heartbeat 추가 긴 쿼리/도구 대기 중 봇이 멈춘 것처럼 보이는 UX를 완화하고, 사용자가 직접 중단 가능
turn 결과, trace, feedback을 파일 기반으로 남김 logs/analyst-bot/ 아래 audit/trace/feedback JSONL 기록 추가 Slack thread만으로는 사후 품질 개선과 장애 재현이 어려움
Metabase MCP를 분석 세션 도구로 연결하고, 카드/대시보드는 봇이 직접 생성 METABASE_URL/METABASE_API_KEY가 있을 때만 --strict-mcp-config --mcp-config로 Metabase MCP 주입. Slack 링크는 별도 public URL 사용 사용자에게 SQL 복붙을 넘기지 않고, 필요할 때 시각화 링크를 바로 제공하기 위함
Slack 한도 초과 시 compact/minimal fallback 현재는 2,500자 final guardrail과 chunk fallback으로 축소 구현 단일 Python 파일 구조에서 과한 block renderer를 넣기보다 먼저 P0 문제를 제거
